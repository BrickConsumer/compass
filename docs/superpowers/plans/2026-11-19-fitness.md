# Fitness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional Fitness place: routines kept as checklists, sessions ticked off from them, a record of what was done, and bests and measures kept by hand, with today's training on Home and one more figure in the Weekly review.

**Architecture:** As in pieces 1 and 2: pure rules in `src/domain/`, tested first; the Zustand store gains four lists (`routines`, `workouts`, `bests`, `measures`) and one setting (`settings.fitness`); pages read the store through the domain functions. A week is never stored: its rows are worked out from the routines and the sessions, as a habit's week is. Home and the Weekly review read the same function the place does, so there is no second copy. On screen a session is a "session"; in the data it is a `workout`, because `sessions` holds study sessions.

**Tech Stack:** React 19.3, TypeScript 7.0, React Router 8.5, Zustand 5.1, date-fns 4.4, Lucide React 1.73, Tailwind CSS 4.3, Motion 14.14, Vitest 5.1, Playwright 1.65.

**As executed, on 19 November:** every step below was done, and Oliver approved the commit the same day. Five things were done differently, each for a reason given in the spec's section 19 and the testing report's section 16: a save's lists are not cut to their limits, which Task 1 had asked for; the test for a place with no routines is with Task 8's, where its words are built; the shared rows gained a few options their three users need; the width test measures Home from 375 px, because Home is wider than a 320 px screen with or without Fitness; and the review of the whole change led to six fixes.

## Global Constraints

- Long words wrap (`[overflow-wrap:anywhere]`) wherever the user's own text is shown.
- Delete uses an Undo toast, never a confirmation, except a line in a routine's editor (section 15). No control that looks real and does nothing.
- British English. Copy is exactly as the spec gives it.
- No test sends a request off the machine.
- Every existing unit and browser test passes unchanged: 313 unit, 159 browser. New tests go in files of their own.

**Interfaces:**
- Consumes: the types of Task 1; `Progress` from `tasks.ts`; `weekdayOf`, `weekDays` from `dates.ts`.
- Produces:
  - `isSet(routine: Routine, date: ISODate): boolean`: one of its weekdays, on or after `createdOn`.
  - `type SessionState = 'ahead' | 'due' | 'past' | 'started' | 'finished'`: set for a day to come, set for today, set for a day that has passed, started, finished.
  - `interface SessionRow { date: ISODate; name: string; state: SessionState; routine?: Routine; workout?: Workout }`. `name` is the session's when it is started and the routine's otherwise. `routine` is absent when the session's routine is gone.
  - `sessionsForDay(routines: Routine[], workouts: Workout[], date: ISODate, today: ISODate): SessionRow[]`: the day's set sessions in the order of the routines, each as its session once started, then the day's other sessions in the order they were started.
  - `sessionsForWeek(routines: Routine[], workouts: Workout[], weekStart: ISODate, today: ISODate): SessionRow[]`
  - `sessionCount(rows: SessionRow[]): Progress`; `ticked(workout: Workout): Progress`
  - `lastDone(workouts: Workout[], routineId: string): ISODate | undefined`: the latest day of its finished sessions.
  - `offers(routines: Routine[], workouts: Workout[], today: ISODate): Routine[]`: the routines not in today's rows, a routine never done first, then the longest ago, level ones in their own order.
  - `isRestDay(routines: Routine[], workouts: Workout[], today: ISODate): boolean`: today has no row, and some routine has a fixed day.
  - `recentWorkouts(workouts: Workout[]): Workout[]`: finished ones, newest day first, and of two for one day the later finished first.
